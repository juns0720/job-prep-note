# 지원서 인적사항 입력 절차 (AI용)

AI 코딩 도구가 지원서를 채울 때 따르는 절차다. 사용자용 안내는 [인적사항 자동 입력 가이드](../profile-autofill.md)에 있다.
명령어는 AI가 직접 실행한다. 사용자에게는 클릭할 위치와 작업 결과를 쉬운 말로 설명한다.

## Aside 연결 준비

사용자가 Aside 앱을 설치하고 로그인한 상태에서 시작한다. `aside` MCP 도구가 이미 연결되어 있다면 이 절을 건너뛴다.

1. `aside --version`으로 CLI 설치 여부를 확인한다. 없으면 설치한다.
   - macOS: `curl -fsSL https://releases.aside.com/install.sh | bash`. 설치 위치는 보통 `~/.local/bin/aside`다.
   - Windows이거나 설치가 안 되면 사용자에게 Aside **Settings → Developers**에서 CLI 설치를 눌러 달라고 한다.
     설치 화면에 표시된 CLI 경로를 사용한다.
2. `aside login --email "<사용자 이메일>"`로 CLI에 로그인한다. 명령이 실행되는 동안 사용자에게 Aside
   **Settings → Account → Devices**에서 코드를 승인하도록 안내한다. `Signed in as ...`가 표시되면 로그인이 완료된 상태다.
3. MCP 서버로 등록한다.
   - Claude Code: `claude mcp add --scope user aside -- aside mcp` (`aside`를 찾지 못하면 CLI 전체 경로 사용)
   - Codex: `codex mcp add aside -- aside mcp`
4. 등록한 뒤에는 도구가 바로 안 보일 수 있다. 사용자에게 AI 도구를 새로 열고 다시 요청해 달라고 한다.
   연결되면 `exec`와 `repl` 도구를 사용할 수 있다.

`.env.local`이 없으면 `.env.local.example`을 복사해 만든다. README 5단계의 Supabase 접속값과 4단계의 앱 로그인 이메일, 비밀번호 중 빠진 값을 사용자에게 요청한다.

## 진행 원칙

- 입력할 값이 확인된 항목은 계속 채운다. 값이 없거나 선택지가 맞지 않는 항목은 결과 보고에 적고 다음 항목으로 넘어간다. 문장을 줄여야 하는 경우에는 아래 "값 맞추기" 기준을 따른다.
- 페이지를 이동하기 전과 작업 마지막에 임시 저장한다. 임시 저장 버튼이 없다면 다음 단계로 이동할 때 저장되는지 확인한다. 마지막에 미리보기 화면이 있으면 입력한 값이 저장됐는지 대조한다.
- 이미 채워진 항목도 인적사항과 대조한다. 값이 다르면 인적사항에 저장된 값으로 고친다.

## 작업 순서

1. 앱의 인적사항을 파일로 내보낸다.

   ```bash
   node scripts/export-profile.mjs < /dev/null
   ```

   `scripts/out/profile.md`에는 섹션별 입력 규칙과 값이 저장된다. 증명사진과 서류는
   `scripts/out/profile-files/`에 저장되며, `profile.md` 마지막 표에서 각 파일의 로컬 경로를 확인할 수 있다. `scripts/out/`은 커밋 대상에서 제외되어 있다.
2. 아래 "Aside 사용 방법"에 따라 사용자가 열어 둔 지원서 탭을 찾아 양식을 읽는다. 로그인, 회원 가입,
   본인 인증은 사용자가 한다.
3. 입력 규칙과 양식에 맞춰 값을 채운다.
4. [입력 결과 보고](#입력-결과-보고)에 따라 결과를 알린다. 입력하지 못한 항목은 [빠진 항목 추가](#빠진-항목-추가)에 따라 인적사항에 추가한다.

## Aside 사용 방법

- MCP 서버 이름은 `aside`다. `repl` 도구로 Playwright 방식의 JavaScript를 실행한다. `exec`는 Aside의
  브라우저 에이전트가 스스로 판단해 진행하므로 지원서 입력에는 쓰지 않는다.
- `getTabs()`로 지원서 탭을 찾는다.
- 한 페이지의 항목은 `getByLabel`, `fill`, `selectOption`, `check`를 묶어 `repl` 한 번으로 입력한다. 같은 호출에서
  값을 다시 읽어 인적사항 값과 대조한다.
- 한글을 키 입력으로 넣을 때 긴 문장의 일부 글자가 빠질 수 있다. 긴 문장은 값을 직접 설정한 뒤 다시 읽어 대조한다.
- 증명사진과 서류는 `scripts/out/profile-files/`의 파일을 올린다. `setInputFiles`는 **Aside 세션 폴더(`repl`의
  `pwd`) 안의 파일만** 받으므로 `<pwd>/upload/`로 복사해서 올린다. 파일명을 영문으로 받는 사이트가 있어
  복사할 때 `id-photo.jpg`처럼 영문 이름으로 바꾼다.
- `repl`이 "no normal browser window" 오류를 내면 Aside에 일반 창이 없는 것이다. 사용자에게 새 창을 열어
  달라고 한 뒤 다시 시도한다.
- `aside` 도구가 없거나 연결되지 않으면 위의 "Aside 연결 준비"부터 한다.

## 값 맞추기

- 섹션별 **입력 규칙**을 먼저 읽는다. 영문 성명 표기, 수상 우선순위, 글자 수 제한별 문장 등 양식에 맞춰 값을 고르는 기준을 확인한다.
- 날짜처럼 형식만 다른 값은 양식에 맞춘다(`2026-03-01` → `2026.03`).
- 값이 `미기록`이거나 양식 선택지와 맞지 않으면 추측하지 않는다. 빈 칸으로 두고 보고 목록에 적는다.
- 글자 수 제한이 인적사항 문장보다 짧으면 줄이기 전에 사용자에게 확인한다.
- 지원 회사, 직무, 근무지, 지망 순위처럼 지원할 때마다 달라지는 값은 사용자의 요청에서 확인한다.
- 포트폴리오와 이력서는 링크를 먼저 사용한다. 파일만 받는 양식에는 첨부 파일을 올린다. 경력기술서를 글로 받는
  칸에는 **경력기술서** 섹션의 본문을 넣는다.

## 입력 범위

- 개인정보 수집 동의는 필수 항목만 체크하고 선택 항목은 체크하지 않는다.
- 최종 제출은 하지 않는다. 사용자가 직접 한다.
- 비밀번호, 주민등록번호, 여권번호, 계좌 정보는 입력하지 않는다. 인적사항에도 저장하지 않는다.
  이런 항목은 사용자가 직접 처리하도록 안내한다. Aside의 비밀번호 자동 입력도 쓰지 않는다.
- 자기소개서 문항은 이 절차로 채우지 않는다. 사용자가 확정한 문장만 넣는다.

## 입력 결과 보고

입력이 끝나면 아래 내용을 보고한다.

| 구분 | 보고할 내용 |
|---|---|
| 입력한 항목 | 페이지별 입력 항목 수, 양식에 맞춰 바꾼 표기와 형식 |
| 입력하지 못한 항목 | 값이 없거나 선택지가 맞지 않아 비워 둔 항목. 양식에 표시된 이름으로 적는다 |
| 직접 처리할 항목 | 주민등록번호 입력, 본인 인증, 최종 제출 등 |

## 빠진 항목 추가

입력하지 못한 항목은 인적사항에 빈 항목으로 추가한다. 사용자가 나중에 값을 적어 두면 다음 지원서에서 사용할 수 있다.

```bash
node scripts/add-profile-fields.mjs '[{"section":"기본 인적사항","label":"혈액형","note":"OO기업 2026-10-20 양식"}]' < /dev/null
```

- 항목형 섹션에는 값이 빈 항목을, 여러 건 섹션에는 칸을 추가한다. 섹션이 없으면 새로 만든다.
- 긴 글 섹션에는 항목을 추가할 수 없다. 스크립트가 건너뛴 항목은 결과 보고에 남긴다.
- 사용자가 그 자리에서 값을 알려 주면 `"value"`까지 넣는다(항목형만).
- 주민등록번호 등 AI가 입력하지 않는 항목은 추가하지 않는다.

마지막으로 **지원처별 입력 기록** 섹션이 있으면 그 본문에 지원처, 날짜, 채용 사이트, 양식에 맞춰
고른 값, 입력하지 못한 항목을 한 단락으로 남긴다.

## 처음 채울 때

인적사항이 비어 있으면 JSON 파일로 한 번에 가져올 수 있다. 파일 형식은 `scripts/import-profile.mjs` 상단 주석을 따른다.
섹션이 이미 하나라도 있으면 가져오지 않는다.

```bash
node scripts/import-profile.mjs <파일.json> < /dev/null
```
