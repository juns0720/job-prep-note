# 공고 수집기

채용 사이트에서 공고를 모아 오고, 고른 것만 앱의 **공고** 탭에 넣는 도구다.
`scripts/` 아래에 있고 자동으로 돌지 않는다 — 생각날 때 내 컴퓨터에서 직접 돌린다.
서버도 크론도 LLM API도 쓰지 않는다.

```
scripts/sources.json           무엇을 모을지 (검색 주소·직무 코드·거르기 기준)
      ↓  node scripts/collect.mjs        1. 목록만 훑는다 (가볍다)
scripts/out/postings-<날짜>.json  긁어온 것 전부
      ↓  node scripts/pick.mjs           2. 키워드로 고른다 (AI와 같이 골라도 된다)
scripts/out/picked-<날짜>.json    고른 것만
      ↓  node scripts/enrich.mjs <파일>  3. 고른 것만 깊게 판다 (선택)
      ↓                                     자소서 문항 · 전형 조건 · 회사 평판
      ↓  node scripts/import.mjs <파일>  4. 앱에 넣는다
Supabase job_postings          앱의 공고 탭에서 본다
```

`scripts/out/`, `scripts/sources.json`, `scripts/state.json`은 커밋되지 않는다.

## 0. 준비

README의 1~5단계(설치, Supabase, 계정, `.env.local`)를 먼저 끝낸다. 수집기는
`.env.local`의 접속값으로 앱과 같은 계정에 로그인해서 공고를 넣는다.

```bash
cp scripts/sources.example.json scripts/sources.json
```

`.env.local`에 앱 로그인 계정을 적어 두면 넣을 때마다 묻지 않는다(적지 않으면
`import.mjs`가 터미널에서 묻는다. 비밀번호는 화면에 찍히지 않는다).

```
STUDY_NOTE_EMAIL=앱에 로그인하는 이메일
STUDY_NOTE_PASSWORD=앱에 로그인하는 비밀번호
```

## 1. 무엇을 모을지 정하기 — `scripts/sources.json`

예시 파일은 "백엔드 개발 신입"을 찾는 설정이다. 직무가 다르면 검색 주소와 키워드를
자기 것으로 바꾼다.

```json
{
  "regions": [],
  "pick": { "include": [...], "exclude": [...], "newcomerOnly": true },
  "targets": [ { "site": "saramin", ... }, ... ]
}
```

| 키 | 뜻 |
|---|---|
| `regions` | 남길 근무 지역. `["서울", "경기"]`처럼 적으면 근무지가 이걸로 시작하지 않는 공고를 뺀다. 비우면 전국 |
| `pick` | `pick.mjs`가 쓰는 거르기 기준. 2단계에서 설명한다 |
| `targets` | 수집할 대상 목록. 사이트마다 하나씩, 같은 사이트를 여러 번 넣어도 된다 |

`targets`의 공통 키는 이렇다.

| 키 | 뜻 |
|---|---|
| `site` | `saramin` · `jasoseol` · `inthiswork` · `manual` |
| `label` | 알아보려고 붙이는 이름. 수집 결과에 같이 남는다 |
| `enabled` | `false`면 건너뛴다. 지우지 않고 잠시 빼둘 때 |

### 사람인 — 검색 주소를 그대로 붙여넣는다

검색 조건을 코드에 박지 않는다. **사람인에서 원하는 조건(검색어·경력·지역)으로
검색한 뒤 주소창의 주소를 그대로 `url`에 붙여넣는다.** 페이지 번호는 수집기가 알아서 넘긴다.

```json
{
  "site": "saramin",
  "label": "백엔드 신입",
  "url": "https://www.saramin.co.kr/zf_user/search?searchType=search&searchword=백엔드&exp_cd=1",
  "pages": 2
}
```

- `pages`는 몇 쪽까지 읽을지다(최대 10).
- 주소의 `exp_cd=1`이 신입, `loc_mcd=101000,102000`이 서울·경기다. 사이트에서 조건을
  고르면 주소에 알아서 붙는다.
- 같은 공고가 검색어마다 다른 주소로 잡혀서, 공고 번호(`rec_idx`)만 남겨 하나로 합친다.

### 자소설닷컴 — 몇 달치와 직무 코드

대기업·공기업 공채가 몰려 있고, 자소서 문항과 전형 조건까지 준다. 화면이 달력이라
검색 주소가 아니라 **몇 달치를 볼지**와 **직무 코드**로 정한다.

```json
{
  "site": "jasoseol",
  "label": "공채 — 개발",
  "months": 2,
  "dutyGroups": [162, 165, 170]
}
```

직무 코드는 사이트의 직무 트리에서 가져왔다. IT·인터넷 아래는 이렇다
(`scripts/lib/adapters/jasoseol.mjs`의 `DUTY_NAMES`).

| 코드 | 직무 | 코드 | 직무 |
|---|---|---|---|
| 160 | QA | 166 | 네트워크·보안·운영 |
| 161 | 앱개발 | 167 | 빅데이터·AI |
| 162 | 웹개발 | 168 | 게임개발 |
| 163 | 데이터엔지니어·분석·DBA | 169 | HW·임베디드 |
| 164 | 시스템프로그래머 | 170 | SW·솔루션·ERP |
| 165 | 응용프로그래머 | 171 | 서비스기획·PM |

- `dutyGroups`를 안 적으면 162~166, 170 여섯 개를 본다.
- 개발 직군이 아니면 `DUTY_NAMES` 아래쪽의 다른 직무 코드를 찾아 넣는다.
- 이번 달 목록에는 이미 마감된 공고가 섞여 오므로 기본으로 뺀다. 지난 것까지 보려면
  `"includeClosed": true`를 더한다.
- 지역과 경력 조건을 주지 않는다. 신입인지는 제목으로 판단한다.

### 인디스워크 — 태그와 카테고리

사람이 골라 올리는 큐레이션 사이트다. 대기업·스타트업·외국계·공공기관이 섞여 있다.

```json
{
  "site": "inthiswork",
  "label": "IT·개발 신입/인턴",
  "tag": "IT개발",
  "categories": ["신입/인턴"],
  "pages": 2
}
```

- `tag`는 직무(`IT개발`, `데이터분석` …), `categories`는 대상(`신입/인턴`, `주니어경력`)이다.
  사이트에 보이는 이름 그대로 적으면 수집기가 번호를 찾아 쓴다. 한 쪽이 50건이다.
- 마감된 글은 빼고 받는다. 지역은 주지 않는다.
- 제목이 `회사｜공고 제목` 꼴이면 둘로 가른다. 가름표 없이 올라온 글은 회사명이 빈다.

### 직접 모은 주소 — manual

원티드처럼 수집기가 들어갈 수 없는 사이트의 공고는 주소를 직접 넣는다.
목록을 긁지 않고 준 주소만 하나씩 열어 제목 정도만 뽑는다.

```json
{
  "site": "manual",
  "label": "직접 모은 공고",
  "urls": ["https://www.wanted.co.kr/wd/123456"]
}
```

## 2. 수집 — `node scripts/collect.mjs`

```bash
node scripts/collect.mjs                 # 지난번 이후에 올라온 것만
node scripts/collect.mjs --all           # 처음부터 다시
node scripts/collect.mjs --only jasoseol # 한 사이트만
```

결과는 `scripts/out/postings-<날짜>.json`에 쌓인다.

**그냥 돌리면 지난번 수집 이후에 새로 뜬 공고만 모인다.** 언제까지 봤는지는
`scripts/state.json`에 사이트별로 남는다. 처음부터 다시 보고 싶으면 `--all`을 쓰거나
`scripts/state.json`을 지운다.

- 자소설닷컴은 공고가 올라온 시각으로, 인디스워크는 올린 시각 조건으로 거른다.
- 사람인은 검색 결과에 올라온 시각이 없어서 매번 전부 긁는다. 이미 넣어둔 공고는
  임포터가 걸러내므로 중복으로 쌓이지는 않는다.

## 3. 고르기

수집한 공고를 전부 넣으면 목록이 금방 묻힌다. 지원할 만한 것만 추려
`scripts/out/picked-<날짜>.json`으로 만든다. 두 가지 방법이 있고 섞어 써도 된다.

### 방법 A. 키워드로 거르기 — `node scripts/pick.mjs`

```bash
node scripts/pick.mjs                    # out/ 에서 가장 최근 postings 파일
node scripts/pick.mjs <파일>             # 파일을 골라서
node scripts/pick.mjs --show-dropped     # 뺀 공고와 이유도 본다
```

기준은 `sources.json`의 `pick`에 적는다.

```json
"pick": {
  "include": ["백엔드", "서버", "개발자", "웹개발"],
  "exclude": ["프론트", "iOS", "QA"],
  "newcomerOnly": true
}
```

| 키 | 동작 |
|---|---|
| `include` | 제목이나 직무 칸에 하나라도 있어야 남긴다. 비우면 전부 통과 |
| `exclude` | **제목에** 하나라도 있으면 뺀다 |
| `newcomerOnly` | 경력만 뽑는 공고를 뺀다. 경력 칸이 "신입·경력"이면 남기고 "경력 3년↑"이면 뺀다. 경력 칸이 빈 사이트는 제목에 "경력"만 있고 "신입"이 없을 때만 뺀다 |

- 대소문자는 가리지 않는다.
- 직무 칸에 담기는 것은 사이트마다 다르다. 사람인은 직무·스택, 자소설닷컴은 직무 이름
  (`웹개발`, `응용프로그래머` …), 인디스워크는 태그(`IT개발` …)다. 그래서 예시의
  `include`에는 사이트별 직무 이름도 들어 있다.
- `exclude`를 제목에서만 찾는 이유: 사람인은 직무 칸에 "백엔드, 프론트엔드, 풀스택"처럼
  여러 직무를 한꺼번에 적어서, 직무 칸까지 보면 백엔드 공고도 빠진다.
- `exclude`는 깐깐하다. "프론트/백엔드 개발자 채용"처럼 제목에 둘 다 있으면 빠진다.
  `--show-dropped`로 뺀 것을 한 번 훑어보고 키워드를 다듬는다.

남긴 공고마다 걸린 키워드가 `note`에 적힌다. 앱의 공고 상세에서 메모로 보인다.

### 방법 B. AI와 같이 고르기

키워드로는 "스택이 안 맞는 공고" 같은 걸 거르기 어렵다. Claude Code 같은 AI 코딩
도구가 있으면 이 레포를 연 상태에서 이렇게 부탁하면 된다.

```
scripts/out/postings-2026-10-14.json 을 읽고 내가 지원할 만한 공고만 골라서
scripts/out/picked-2026-10-14.json 으로 저장해줘.

찾는 것: <직무·경력·지역·스택을 적는다. 예: 백엔드 신입, 지역 무관, Python이나 Go>
- 경력만 뽑는 공고는 뺀다
- 찾는 직무가 아니면 뺀다
- 원하지 않는 스택 전용이면 뺀다
- 직무나 스택이 안 적힌 통합 공채는 남긴다 (열어 봐야 안다)

파일 모양은 원본과 같게 { "items": [...] } 로 두고, 항목은 고치지 말고 고르기만 한다.
고른 이유는 각 항목의 note에 한 줄로 적는다. picked는 false로 둔다.
```

`pick.mjs`로 한 번 거른 `picked-*.json`을 AI에게 더 줄여 달라고 해도 된다.

### 손으로 고를 때 지킬 것

- 파일 모양은 `{ "items": [ ... ] }`(또는 배열 그대로)다. 항목 하나는 수집 결과의 것 그대로다.
- **`picked`는 `false`로 둔다.** 앱에서 `picked`는 "자기소개서로 옮김"이라는 뜻이라,
  `true`로 넣으면 대기가 아니라 옮김에 들어간다.
- 고른 이유는 `note`에 적는다.

## 4. 상세 채우기 — `node scripts/enrich.mjs` (선택)

```bash
node scripts/enrich.mjs scripts/out/picked-2026-10-14.json
node scripts/enrich.mjs <파일> --no-company   # 회사 평판은 건너뛴다
```

고른 공고만 하나씩 더 열어 본다. 결과는 같은 파일에 덮어쓴다(`--out <파일>`로 바꿀 수 있다).

- **자소서 문항** — 문항 그대로와 글자 수 제한(자소설닷컴). 앱에서 자기소개서로 옮기면
  문항이 바로 만들어진다.
- **전형 조건** — 필기 여부, 졸업 조건, 고용형태, 채용연계형인지(자소설닷컴).
- **회사 채용 페이지** — 실제로 지원하는 곳 주소(자소설닷컴, 인디스워크).
- **회사 평판** — 잡플래닛 평점·회사 평균 연봉·규모. 어느 사이트 공고든 회사명만 있으면 붙인다.

공고 하나에 요청이 두세 번 나가서, 50건이면 몇 분 걸린다. 수집 때마다 할 일이 아니라
따로 뗀 단계다. 건너뛰고 바로 4단계로 가도 된다.

### 회사 평판에는 잡플래닛 쿠키가 필요하다

잡플래닛은 스크립트에서 오는 요청을 403으로 막는다. 브라우저에서 쓰던 쿠키를
`.env.local`에 넣으면 그걸로 요청한다.

1. 잡플래닛에 로그인한다.
2. 개발자도구(F12) → Network 탭 → 아무 요청이나 클릭한다.
3. Request Headers의 `Cookie:` 값을 통째로 복사해 `.env.local`에 넣는다.

```
JOBPLANET_COOKIE=복사한 값 그대로
```

로그아웃하거나 시간이 지나면 만료된다. 403이 나오면 다시 복사한다.
쿠키가 없으면 이 부분만 건너뛴다. 앱의 공고 상세에는 회사명으로 잡플래닛을 찾는
링크가 대신 나온다.

**회사 매칭은 반만 된다.** 검색 결과 맨 위에 광고가 섞여 엉뚱한 회사가 걸리는 일이
잦아서, 받아온 회사명이 공고의 회사명과 이어지지 않으면 버린다. 영문 약자 사명은
잡플래닛이 한글 법인명으로 들고 있어서 자동으로는 못 잇는다. 그런 회사는 링크로 직접 본다.

## 5. 앱에 넣기 — `node scripts/import.mjs`

```bash
node scripts/import.mjs scripts/out/picked-2026-10-14.json
node scripts/import.mjs <파일> --update   # 이미 있는 공고도 덮어쓴다
```

`.env.local`의 계정으로 **앱과 똑같이 로그인해서** 넣는다. service_role 키를 쓰지 않으므로
RLS가 그대로 걸린 채로 들어간다 — 내 계정의 공고로만 들어간다.

- 같은 주소는 한 줄만 남는다(`unique (user_id, url)`).
- 기본은 **이미 있는 공고를 건드리지 않는다.** 다시 수집했다고 해서 매겨둔 메모가 지워지면 안 된다.
- 앱에서 `삭제`한 공고는 행을 지우지 않고 표시만 남긴다. 그래서 다시 수집해도 되살아나지 않는다.

넣은 뒤 앱을 새로고침하면 **공고** 탭에 보인다.

## 앱에서 공고가 놓이는 자리

| 자리 | 언제 | 다시 수집하면 |
|---|---|---|
| **대기** | 아직 안 본 공고 | 새로 뜬 것이 여기 쌓인다 |
| **옮김** | `자기소개서에 추가`를 누른 공고 | 올라오지 않는다 |
| **지움** | `삭제`를 누른 공고 | 올라오지 않는다 |

넘기거나 빼면 대기에서 사라진다. 훑어 내려갈수록 대기가 줄어드니 어디까지 봤는지
따로 기억할 필요가 없다. 둘 다 `대기로 되돌리기`로 꺼낼 수 있다.

목록은 **마감순**과 **최신순**으로 줄 세우고, 그 아래 줄에서 사이트별로 거른다.

## 평소에 돌리는 순서

```bash
node scripts/collect.mjs
node scripts/pick.mjs
node scripts/enrich.mjs scripts/out/picked-<날짜>.json   # 선택
node scripts/import.mjs scripts/out/picked-<날짜>.json
```

## 상대 서버에 대한 태도

- **robots.txt를 돌릴 때마다 확인한다**(`scripts/lib/robots.mjs`). 막은 경로는 건너뛴다.
- 같은 호스트로는 한 번에 하나씩, 요청 사이에 1.5초를 둔다(`scripts/lib/fetch.mjs`).
- 5xx와 네트워크 오류만 두 번까지 다시 시도한다. 404·403은 포기한다.
- robots.txt가 막은 사이트(원티드, 직행, 네이버 카페 등)는 붙이지 않는다.
  그런 곳의 공고는 `manual`로 주소를 직접 넣는다.
- `pages`나 `months`를 크게 잡고 자주 돌리지 않는다. 개인이 하루에 한두 번 돌리는 정도를
  생각하고 만든 도구다.

사이트 구조가 바뀌면 수집이 0건이 되거나 실패할 수 있다. 그때는 해당 어댑터
(`scripts/lib/adapters/<사이트>.mjs`)의 선택자를 고친다.

## 사이트를 하나 더 붙이려면

`scripts/lib/adapters/`에 파일을 하나 만들고 `site`와 `collect(target, log)`를
내보낸 다음, `scripts/collect.mjs`의 `ADAPTERS`에 등록한다. 반환 형태는
`saramin.mjs`가 만드는 객체와 같으면 된다.

```js
{
  source, external_id, url, company, title,
  location, career, employment, sector, due_text, due, raw
}
```

- 인코딩은 `fetchText`가 응답 헤더의 charset을 보고 알아서 디코딩한다.
- HTML이 아니라 JSON을 주는 곳은 `fetchJson`을 쓴다. POST가 필요하면
  `{ method: "POST", body }`를 넘긴다 — 자소설닷컴이 그런 경우다.
- 앱의 사이트 필터에 이름을 붙이려면 `components/job/JobAside.tsx`의 `SOURCE_NAMES`에 더한다.

## 어디서 무엇이 오나

| 사이트 | 쓸 만한 것 | 한계 |
|---|---|---|
| 사람인 | 중소·중견 공고가 많다. 지역·경력·마감이 다 붙어 온다 | 올라온 시각이 없어 매번 전부 긁는다 |
| 자소설닷컴 | 대기업·공기업 공채. 마감 시각이 분 단위로 정확하고 **자소서 문항과 전형 조건까지** 준다 | 지역과 경력 조건을 주지 않는다 |
| 인디스워크 | 사람이 골라 올리는 큐레이션. 회사 채용 페이지로 바로 이어진다 | 직무 태그가 넓어서(`IT개발`) 세부 직무로 못 좁힌다. 지역을 주지 않는다 |
| 원티드 · 직행 · 네이버 카페 | — | robots.txt가 막았다. `manual`로 주소를 직접 넣는다 |
