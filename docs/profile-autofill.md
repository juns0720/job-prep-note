# AI로 지원서 인적사항 채우기

채용 사이트 지원서의 인적사항 칸(이름, 연락처, 학력, 자격증 …)을 AI가 앱의 **인적사항** 탭 값으로
채우게 할 수 있습니다. 지원서마다 같은 값을 다시 입력하지 않아도 됩니다.

## 처음 사용하기

1. [README의 배포 설정](../README.md#0-준비물)을 완료합니다.
2. 앱의 **인적사항** 탭에 값을 적습니다. 섹션은 세 가지 형식이 있습니다.

   | 형식 | 쓰는 곳 | 예시 |
   |---|---|---|
   | 항목 | 항목 · 값 · 비고를 한 줄씩 | 기본 인적사항, 주소, 병역 |
   | 여러 건 | 같은 칸을 가진 건을 여러 개 | 학력, 자격증, 수상 |
   | 긴 글 | 글 하나 | 경력기술서, 지원처별 입력 기록 |

   섹션마다 **입력 규칙**에 양식에 맞추는 방법(영문 이름 표기, 날짜 형식 …)을 적어 두면 AI가 따릅니다.
   증명사진과 서류 파일은 같은 탭의 **첨부 파일·링크**에 올립니다.
3. Claude Code처럼 저장소 파일을 읽고 명령을 실행할 수 있고, **브라우저를 조작할 수 있는** AI 코딩
   도구(Claude in Chrome, Playwright MCP 등)에서 본인의 저장소를 엽니다.
4. 브라우저에서 채용 사이트에 로그인하고 지원서 작성 화면을 열어 둔 다음 요청합니다.

```text
열어 둔 OO기업 지원서의 인적사항을 채워 줘.
docs/profile-autofill.md의 절차를 따라 줘.
지원 직무는 백엔드 개발, 근무지는 서울이야.
```

지원 직무, 근무지, 지망 순위처럼 지원할 때마다 달라지는 값은 요청에 같이 적습니다.
처음 연결할 때는 README 5단계의 Supabase 접속값과 4단계의 앱 로그인 계정이 필요합니다.

### 이미 정리해 둔 인적사항이 있다면

다른 곳에 정리해 둔 인적사항이 있으면 AI에게 옮겨 달라고 요청할 수 있습니다.

```text
이 인적사항을 scripts/import-profile.mjs 형식의 JSON으로 만들어서 앱에 넣어 줘.
JSON 파일은 저장소 밖에 두고, 넣은 뒤에는 지워 줘.
```

개인정보가 들어가므로 JSON 파일은 저장소에 커밋하지 않습니다.

## 끝나면 확인할 것

AI가 세 묶음으로 알려 줍니다.

1. **채운 칸** — 페이지별로 넣은 칸과, 양식에 맞춰 바꾼 값
2. **못 채운 칸** — 인적사항에 값이 없거나 선택지가 맞지 않아 비워 둔 칸
3. **직접 할 칸** — 주민등록번호, 본인 인증, 최종 제출처럼 직접 해야 하는 것

못 채운 칸은 인적사항 탭에 빈 칸으로 더해집니다. 빈 칸은 빨간 `미기록`으로 보이니, 값을 채워 두면
다음 지원서부터 자동으로 들어갑니다. **최종 제출은 직접 합니다.**

## AI가 따르는 절차

이 아래는 AI가 읽는 부분입니다.

### 진행 원칙

- 중간에 묻지 않고 끝까지 진행한다. 목표는 모든 칸 채우기다. 값이 없어 못 채운 칸은 멈추지 않고
  적어 두고 다음 칸으로 넘어간다.
- 임시저장 버튼이 있으면 페이지를 옮기기 전과 마지막에 항상 누른다. 임시저장 버튼이 없는 단계는
  '다음 단계'가 저장하면서 넘어간다. 마지막에 지원서 확인(미리보기) 화면이 있으면 거기서 값이 다
  저장됐는지 대조한다.
- 이미 채워진 칸도 인적사항과 대조해 다르면 인적사항 값으로 고친다.

### 흐름

1. 인적사항을 뽑는다.

   ```bash
   node scripts/export-profile.mjs < /dev/null
   ```

   `scripts/out/profile.md`에 섹션마다 입력 규칙·값이, `scripts/out/profile-files/`에 증명사진과
   서류 파일이 생긴다. md 끝의 표에 파일마다 로컬 경로가 있다. `scripts/out/`은 커밋되지 않는다.
2. 사용자가 열어 둔 지원서 탭을 찾아 양식을 읽는다. 로그인, 회원 가입, 본인 인증은 사용자가 한다.
3. 채운다. 한 페이지의 칸은 한 번에 넣고 값을 다시 읽어 인적사항과 대조한다. 한글을 키 입력으로
   넣으면 긴 문장에서 글자가 빠질 수 있어서, 긴 문장은 값을 직접 설정한 뒤 다시 읽어 대조한다.
4. 증명사진과 서류는 `scripts/out/profile-files/`의 파일을 파일 칸에 올린다. 브라우저 도구가 특정
   폴더 안의 파일만 받으면 그 폴더로 복사해서 올린다. 파일명을 영문으로 받는 사이트가 있어 복사할
   때 `id-photo.jpg`처럼 영문 이름으로 바꾼다.
5. 끝나면 위의 세 묶음으로 보고하고, 못 채운 칸을 인적사항에 빈 칸으로 더한다(아래 "빠진 칸 더하기").

### 값 맞추기

- 섹션마다 **입력 규칙**을 먼저 읽는다. 영문 성명 표기, 수상 우선순위, 글자 수 제한별 문장처럼
  양식에 따라 고르는 방법이 거기 있다.
- 날짜처럼 형식만 다른 값은 양식에 맞춘다(`2026-03-01` → `2026.03`).
- 값이 `미기록`이거나 양식 선택지와 맞지 않으면 추측하지 않는다. 빈 칸으로 두고 보고 목록에 적는다.
- 글자 수 제한이 인적사항 문장보다 짧으면 줄이기 전에 사용자에게 확인한다.
- 지원 회사, 직무, 근무지, 지망 순위처럼 지원할 때마다 달라지는 값은 사용자의 요청에서 확인한다.
- 포트폴리오·이력서는 링크를 먼저 쓴다. 파일만 받으면 첨부 파일을 낸다. 경력기술서를 글로 받는
  칸에는 **경력기술서** 섹션의 본문을 넣는다.

### 하는 것과 하지 않는 것

- 개인정보 수집 동의는 필수 항목만 체크하고 선택 항목은 체크하지 않는다.
- 최종 제출은 하지 않는다. 사용자가 직접 한다.
- 비밀번호, 주민등록번호, 여권번호, 계좌 정보는 입력하지 않는다. 인적사항에도 저장하지 않는다.
  이런 칸은 "직접 할 칸"으로 보고한다. 브라우저의 비밀번호 자동 입력도 쓰지 않는다.
- 자기소개서 문항은 이 절차로 채우지 않는다. 사용자가 확정한 문장만 넣는다.

### 빠진 칸 더하기

못 채운 칸은 인적사항에 빈 칸으로 더해서 다음 지원서부터는 값만 채우면 들어가게 한다.

```bash
node scripts/add-profile-fields.mjs '[{"section":"기본 인적사항","label":"혈액형","note":"OO기업 2026-10-20 양식"}]' < /dev/null
```

- 항목형 섹션이면 값이 빈 항목을, 여러 건 섹션이면 칸을 더한다. 섹션이 없으면 새로 만든다.
- 사용자가 그 자리에서 값을 알려 주면 `"value"`까지 넣는다(항목형만).
- 직접 할 칸(주민등록번호 등)은 더하지 않는다.

마지막으로 **지원처별 입력 기록** 섹션이 있으면 그 본문에 지원처, 날짜, 채용 사이트, 양식에 맞춰
고른 값, 못 채운 칸을 한 단락으로 남긴다.

### 처음 채울 때

인적사항이 비어 있을 때 한 번만 JSON으로 넣는다. 모양은 `scripts/import-profile.mjs` 상단 주석에 있다.
이미 섹션이 하나라도 있으면 아무것도 하지 않는다.

```bash
node scripts/import-profile.mjs <파일.json> < /dev/null
```
