# 인적사항 자동 입력

공채 사이트 지원서의 인적사항 칸을 클로드가 Aside 브라우저로 채운다. 값은 study-note의
**인적사항** 탭에 있다. 이 문서는 클로드가 따르는 절차다.

## 진행 원칙 (2026-10-19 사용자가 정함)

- **중간에 묻지 않고 끝까지 진행한다.** 페이지 이동, 임시저장, 인적사항과 다른 값 고치기를 확인받지 않는다.
- 목표는 **모든 칸 채우기**다. 못 채운 칸은 리스트업해서 인적사항을 보완한다.
- **임시저장은 무조건 누른다.** 페이지를 옮기기 전과 마지막에 누른다.
- 이미 채워진 칸도 인적사항과 대조해 다르면 인적사항 값(최신 입력 규칙 포함)으로 고친다.

## 흐름

1. 사용자가 이 저장소의 클로드 세션에 "OO기업 인적사항 입력하자"라고 한다.
2. 클로드가 인적사항을 뽑는다.

   ```bash
   node scripts/export-profile.mjs < /dev/null
   ```

   `scripts/out/profile.md`에 섹션마다 입력 규칙·값이, `scripts/out/profile-files/`에 증명사진과
   서류 파일이 생긴다. md 끝의 표에 파일마다 로컬 경로가 있다.
3. Aside 브라우저에서 사용자가 로그인해 둔 지원서 페이지를 찾아 양식을 읽고 값을 맞춘다.
4. 채운다. 값이 없어 못 채운 칸은 **멈추지 않고** 적어 두고 다음 칸으로 넘어간다.
5. 끝나면 보고하고, 못 채운 칸을 인적사항에 빈 칸으로 더한다(아래 "빠진 칸 더하기").

## Aside 다루기

- MCP 서버 이름은 `aside`다. `repl` 도구로 Playwright 방식의 JavaScript를 실행한다.
  `exec`는 브라우저 에이전트가 스스로 판단해 진행하므로 지원서 입력에는 쓰지 않는다.
- `getTabs()`로 지원서 탭을 찾는다. 로그인, 회원 가입, 본인 인증은 사용자가 한다.
- 한 페이지의 칸은 `getByLabel`, `fill`, `selectOption`, `check`를 묶어 `repl` 한 번으로 넣고,
  같은 호출에서 값을 다시 읽어 인적사항 값과 대조한다.
- 한글을 키 입력으로 넣으면 긴 문장에서 글자가 빠진다. 긴 문장은 값을 직접 설정한 뒤 다시 읽어 대조한다.
- 증명사진과 서류는 `scripts/out/profile-files/`의 로컬 경로로 파일 칸에 올린다.
- `repl`이 "no normal browser window" 오류를 내면 Aside에 일반 창이 없는 것이다. 사용자에게
  새 창을 열어 달라고 한 뒤 다시 한다.
- Aside가 연결되지 않았거나 사이트가 Aside에서 안 돌면 알리고 Claude in Chrome으로 할지 묻는다.

## 값 맞추기

- 섹션마다 **입력 규칙**을 먼저 읽는다. 영문 성명 표기, 수상 우선순위, 글자 수 제한별 문장처럼
  양식에 따라 고르는 방법이 거기 있다.
- 날짜처럼 형식만 다른 값은 양식에 맞춘다(`2026-03-01` → `2026.03`).
- 값이 `미기록`이거나 양식 선택지와 맞지 않으면 추측하지 않는다. 빈 칸으로 두고 보고 목록에 적는다.
- 글자 수 제한이 인적사항 문장보다 짧으면 줄이기 전에 사용자에게 확인한다.
- 지원 회사, 직무, 근무지, 지망 순위처럼 지원할 때마다 달라지는 값은 사용자의 요청에서 확인한다.
- 포트폴리오·이력서는 링크를 먼저 쓴다. 파일만 받으면 첨부 파일의 Word를 낸다. 경력기술서를
  글로 받는 칸에는 **경력기술서** 섹션의 본문을 넣는다.

## 하는 것과 하지 않는 것

- **개인정보 수집 동의는 필수 항목만 체크하고 선택 항목은 체크하지 않는다.** 2026-10-19에 사용자가 정했다.
- 최종 제출은 하지 않는다. 사용자가 직접 한다. 임시저장은 페이지를 옮기기 전과 끝날 때 항상 누른다.
- 비밀번호, 주민등록번호, 여권번호, 계좌 정보는 입력하지 않는다. 인적사항에도 저장하지 않는다.
  이런 칸은 "직접 입력할 칸"으로 보고한다. Aside의 비밀번호 자동 입력도 쓰지 않는다.
- 자기소개서 문항은 이 절차가 아니다. CLAUDE.md의 "자소서를 쓸 때"를 따르고, 사용자가 확정한 문장만 넣는다.

## 보고

입력이 끝나면 세 묶음으로 알린다.

1. **채운 칸** — 페이지별로 몇 칸을 넣었는지, 양식에 맞춰 바꾼 값(표기·형식)
2. **못 채운 칸** — 인적사항에 값이 없거나 선택지가 맞지 않아 비워 둔 칸. 칸 이름 그대로
3. **직접 할 칸** — 주민등록번호·본인 인증·최종 제출처럼 사용자가 해야 하는 것

## 빠진 칸 더하기

못 채운 칸은 인적사항에 빈 칸으로 더해서 다음 지원서부터는 값만 채우면 들어가게 한다.

```bash
node scripts/add-profile-fields.mjs '[{"section":"기본 인적사항","label":"혈액형","note":"OO기업 2026-10-20 양식"}]' < /dev/null
```

- 항목형 섹션이면 값이 빈 항목을, 여러 건 섹션이면 칸을 더한다. 섹션이 없으면 새로 만든다.
- 사용자가 그 자리에서 값을 알려 주면 `"value"`까지 넣는다(항목형만).
- 직접 할 칸(주민등록번호 등)은 더하지 않는다.
- 인적사항 탭에서 빈 칸은 빨간 `미기록`으로, 목록에는 `빈 칸 N`으로 보인다.

마지막으로 **지원처별 입력 기록** 섹션 본문에 지원처, 날짜, 채용 사이트, 양식에 맞춰 고른 값,
못 채운 칸을 한 단락으로 남긴다. 앱 화면에서 쓰거나, 사용자에게 붙여 넣을 문장을 준다.

## 처음 채울 때

인적사항이 비어 있을 때 한 번만 JSON으로 넣는다. 모양은 `scripts/import-profile.mjs` 상단 주석에 있다.
개인정보가 들어가므로 JSON은 저장소에 두지 않는다.

```bash
node scripts/import-profile.mjs <파일.json> < /dev/null
```
